## 一、意图识别的本质

### 1.1 核心定义
**意图识别 = 从一堆枚举里面挑出一个**

更完整的理解是两件事：
| 维度 | 说明 | 对应技术 |
|:---|:---|:---|
| 识别业务流程 | 确定用户要进入哪个业务流 | Intent Classification |
| 抽取关键参数 | 提取该流程需要的参数 | Slot Filling（槽位填充）|

### 1.2 输出形态演进
```
简单版：{"intent": "product_recommendation"}

完整版：{
  "intent": "product_recommendation",
  "category": "服装",
  "subcategory": "裤子",
  "budget_max": 3000,
  "usage_scenario": "拍照"
}
```

## 二、意图识别的时机（三种模式）

| 模式 | 做法 | 适用场景 | 面试推荐度 |
|:---|:---|:---|:---|
| **混合式** | 与用户输入规范化一起做 | 简单系统、小型Agent、领域专属Agent | ⭐⭐ |
| **独立前置式** ⭐ | 进入ReAct/TAO循环前，先独立做一次意图识别 | 大多数工程化系统 | ⭐⭐⭐⭐⭐ |
| **循环内置式** | 在ReAct/TAO循环中动态完成 | 灵活但难调试，常与Slot Filling结合 | ⭐⭐⭐ |

> **面试建议**：优先回答**第二种（独立前置式）**，边界清晰、可评估、可调试，符合工程化思路。

---

## 三、为什么必须有意图识别？（三大核心原因）

### 3.1 影响Prompt/Spec加载
- **售前**：考虑预算、场景、品牌偏好、历史浏览、性价比
- **售后**：关注订单状态、发货情况、退款期限、售后政策
- → 两套完全不同的业务规范

### 3.2 影响上下文组织
| 场景 | 上下文重点 |
|:---|:---|
| 售前 | 用户画像、价格偏好、历史购买、浏览行为、商品候选集 |
| 售后 | 用户订单、物流状态、售后政策、支付记录、退款记录 |

> 售后场景塞用户画像 = **浪费上下文窗口**

### 3.3 影响工具选择
- 商品推荐 → 商品检索工具
- 订单查询 → 订单系统
- 退款申请 → 售后系统
- 内容生成 → 文档生成工具

**极端形态**：意图识别 → 分发到不同**子Agent** → 子Agent内部可进一步意图识别

### 🔥 面试金句
> "意图识别不是为了给用户输入贴标签，而是为了决定Agent后面**应该怎么想、加载什么上下文、调用什么工具、进入哪个业务流程**。"

## 四、意图识别提示词工程（四大要素）

### 4.1 定义清楚候选意图
```
# 候选意图
- product_recommendation：用户希望系统推荐商品...
- product_comparison：用户希望比较两个或多个商品...
- product_query：用户希望查询某个商品信息...
- unclear：用户输入信息不足，无法判断具体意图
```
**关键原则**：**禁止无中生有** —— 不允许模型自己发明意图，需代码校验兜底

### 4.2 定义清楚意图边界
> 易混淆意图必须澄清边界

| 用户输入 | 正确意图 |
|:---|:---|
| "3000块以内有什么手机推荐？" | product_recommendation |
| "iPhone 16的电池容量是多少？" | product_query |
| "iPhone 16和小米15哪个更适合拍视频？" | product_comparison |

### 4.3 定义清楚意图参数（Slot）
```
category：商品类目（手机、笔记本电脑、耳机）
sub_category：更细分类目（游戏本、轻薄本、降噪耳机）
budget_min/budget_max：预算区间
usage_scenario：使用场景（办公、游戏、通勤、送礼）
brand_preference：品牌偏好

# 通用参数
must_have_features：必须满足的特性
nice_to_have_features：加分项
hard_constraints：硬约束
soft_preferences：软偏好
```

### 4.4 加入Few-shot
- 不需要很多，**关键是覆盖容易混淆的边界**
- 可加入**正反两方面例子**明确界定
- 意图特别多时 → 用**层次意图、决策树**解决窗口限制

## 五、识别不出来的处理（两个出口）

| 类型 | 场景 | 处理方式 |
|:---|:---|:---|
| **unsupported** | 意图完全不在候选中 | **拒识**（拒绝识别）|
| **unclear** | 意图混淆 / 参数不足 | **澄清**（主动追问）|

### 5.1 澄清示例
```json
{
  "intent": "product_recommendation",
  "slots": {"category": "衣服"},
  "missing_slots": ["price"],
  "need_clarification": true,
  "clarification_question": "你想让我推荐多少钱的商品呢？"
}
```

> **理念**：好的回答 > 快的回答。先收集完整参数，再回答。

### 5.2 拒识示例
- 用户："帮我生成一个奥特曼动画"
- → 超出电商Agent能力范围，明确拒绝

## 六、三层意图识别解决方案 ⭐⭐⭐（核心）

```
┌─────────────────────────────────────┐
│  第一层：代码层意图识别               │
│  • 页面引导（点击按钮"下一步"）        │
│  • 关键字提取 / 正则匹配              │
│  • 规则引擎（依赖规范化后的输入）      │
│  特点：快、准、便宜、稳定              │
├─────────────────────────────────────┤
│  第二层：轻量级大模型（Flash/Mini）   │
│  • 处理不适合写死规则、无需深度推理的输入 │
│  • 例："帮我推荐一个手机"             │
│  特点：快 + 省                        │
├─────────────────────────────────────┤
│  第三层：深度推理大模型               │
│  • 表达非常复杂                       │
│  • 强依赖上下文                       │
│  • 多轮对话中意图切换                  │
│  • 用户输入包含多个意图                │
│  • 需要根据上下文补全隐含信息           │
│  特点：能力强、成本高、速度慢           │
└─────────────────────────────────────┘
         ↓ 逐层降级：第一层未识别 → 第二层 → 第三层
```

### 6.1 关键问题：为什么不跳过第二层直接用第三层？

**答案**：大多数用户输入意图明确，轻量级模型**准确率高 + 响应速度快**

> 作者立场：**效果 > 效率** —— 用户能接受多等几秒得好结果，不能接受快几秒得坏结果

### 6.2 "识别出来"的判定标准（第二层）

```json
{"intent": "product_recommendation", "confidence": 0.87}
```

| 置信度区间 | 处理方式 |
|:---|:---|
| > 0.85 | 直接接受 |
| 0.6 ~ 0.85 | 进入仲裁或澄清 |
| < 0.6 | 交给下一层深度推理模型 |

> ⚠️ 注意：大模型的confidence是**"自我判断分数"**，非真实概率。建议结合**规则命中、向量相似度、历史准确率**等信号综合判断。

## 七、结合Slot Filling的完整形态

### 7.1 核心机制
意图识别不仅要找出**意图枚举值**，还要**找全所有参数**

### 7.2 完整输出示例
```json
{
  "intent": "product_recommendation",
  "slots": {
    "category": "笔记本电脑",
    "usage_scenario": "写代码",
    "soft_preferences": ["轻一点"]
  },
  "missing_slots": ["budget_max"],
  "need_clarification": false
}
```

### 7.3 高级做法：ReAct/TAO循环中补全槽位
```
意图识别 → 发现missing_slots → 进入对话循环追问 → 
用户补充信息 → 更新slots → missing_slots为空 → 执行业务
```

### 7.4 约束处理（面试加分项）

| 约束类型 | 定义 | 示例 |
|:---|:---|:---|
| **硬约束** | 必须满足，无论如何 | "不要改动A接口" |
| **软约束** | 努力满足，无法满足可告知用户 | "最好是牛仔裤" |

> 🔥 **面试加分点**：主动提及约束要**贯穿整轮对话全过程**，未满足软约束时**明确告知用户**

## 八、评估意图识别效果

### 8.1 基础指标

| 指标 | 说明 |
|:---|:---|
| **Top-K Accuracy** | 标准答案在K个候选意图中即命中 |
| **Top1 Accuracy** ⭐ | 第一个意图即正确（最常用）|

### 8.2 进阶指标

**分意图准确率**
- 防止"全部猜高频意图"的作弊行为
- 特别关注低频但重要的意图（退款、投诉）

**拒识和澄清指标**
| 指标 | 含义 |
|:---|:---|
| 拒识准确率 | 该拒识时是否正确拒识 |
| 误拒率 | 本来能处理，错误拒识 |
| 漏拒率 | 本该拒识，强行归类 |
| 澄清触发准确率 | 缺关键信息时是否正确追问 |
| 澄清后收敛率 | 追问后任务是否顺利推进 |

**Slot Filling指标**
| 指标 | 含义 |
|:---|:---|
| 槽位准确率 | 抽出值是否正确 |
| 槽位召回率 | 用户信息是否被抽出 |
| 必填槽位完整率 | 启动流程必需槽位是否齐备 |
| 槽位更新准确率 | 多轮对话中新信息是否正确覆盖旧信息 |
| **约束识别准确率** ⭐ | 硬约束和软偏好是否识别正确（当前Agent最差的一块）|

**间接评估信号**
- 用户说"不是，我不是这个意思""你理解错了" → 上一轮意图识别失败
- 整体任务成功率（意图识别不准 → 任务必然失败）

## 九、准确率参考与面试话术

### 9.1 行业参考数据

| Agent类型 | Top1 Accuracy | 说明 |
|:---|:---|:---|
| **专属领域Agent** | **99%+** | 领域小、意图少、输入规范，面试建议用此数据 |
| 通用Agent | 80%-90% | 意图开放，水分较大 |

### 9.2 面试应对策略

| 面试官质疑 | 回应策略 |
|:---|:---|
| **"太高了吧，吹牛？"** | ① 专属领域，总共就几个意图（如仅支持查询订单、发起退货）<br>② 用户输入简单规范，toB/内部Agent特点 |
| **"太低了吧，水平差？"** | ① 当前实现较简单，正在优化<br>② 展开讲优化方案（三层机制、Slot Filling等）|

### 9.3 万金油回答框架
> "目前Top1 Accuracy在**XX%**（根据领域说具体数字），基于**三层识别机制+Slot Filling+约束识别**，测试集覆盖标准表达、口语化、槽位缺失、拒识、易混淆样本等场景，持续迭代中。"

## 十、测试集构建（五大必覆盖场景）

| 场景 | 测试重点 |
|:---|:---|
| **标准表达** | 最基础的意图识别能力 |
| **口语化表达** | 病句、缺省、指代（结合用户输入规范测试）|
| **槽位缺失输入** | 缺少必要参数时的处理 |
| **拒识** | 明确应拒绝的输入 |
| **容易混淆的样本** | 相近输入但意图差别大 |

**加分场景**（时间充裕时）：
- 跨轮补充、识别约束、意图切换、多意图输入

## 十一、核心总结

| 要点 | 内容 |
|:---|:---|
| 面试禁忌 | 只说"调用一次大模型判断" |
| 工程化答案 | 三层机制 + Slot Filling + 拒识/澄清 + 指标 + 测试集 |
| 本质认知 | 意图识别决定Agent"后面怎么想、加载什么、调用什么、进入哪" |
| 效果原则 | 效果 > 效率，好的回答 > 快的回答 |
| 未来趋势 | 大模型能力增强后，意图识别可能弱化，但领域优化仍有必要 |

## 十二、评论区精华补充

| 问题 | 作者回应 |
|:---|:---|
| 编程智能体不做意图识别，直接进loop | 意图识别本质是"搞清楚目标"，通用Agent可用其他手段，专属领域仍建议保留 |
| 主Agent内识别意图+prompt增强（加载md文件）| 属于"循环内置式"，代码更简洁但新人难维护 |
| 多意图/三级意图成百上千怎么处理 | ①静态映射 ②向量检索/规则预筛选 ③带候选意图的分层识别 ④激进做法：一二级全扔给大模型 ⑤前端界面引导 |
| 罕见场景无法构建测试集 | 让AI（如ChatGPT）帮你生成，开发前应有市场调研 |

**最终面试话术结构**：
```
"我们的意图识别采用三层机制：第一层代码规则处理高频确定性输入（如'继续'）；
第二层轻量模型处理明确但规则覆盖不到的输入，输出置信度，高置信直接走，
中置信仲裁/澄清，低置信降级；第三层深度模型处理复杂、多轮、多意图场景。
同时结合Slot Filling确保参数完整，区分硬约束软约束并贯穿对话全程。
评估上关注Top1 Accuracy、分意图准确率、拒识/澄清指标、槽位完整率和约束识别准确率，
测试集覆盖标准/口语化/缺失/拒识/混淆五类场景，目前Top1达到XX%。"
```
